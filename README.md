# sasaOrange 的小说站

用 VitePress 搭的在线书架，可以放多部作品（小说、语录集、随笔都行）。

**作品直接放在 `docs/novels/` 里，一个文件夹一部作品**，存盘网站就更新；
书架上点一本书就直接从第一章开始读。

## 日常使用

```bash
pnpm docs:dev         # 本地预览（自动同步 + 监听作品目录），默认 http://localhost:5173
pnpm docs:build       # 构建静态站到 docs/.vitepress/dist
pnpm docs:preview     # 预览已构建的站点
pnpm docs:sync        # 只更新生成的书架页/作品页，不启动服务
```

`docs:dev` 会先同步一次并**一直监听 `docs/novels/`**：改文字即时生效；
新增或删除章节会自动重启一次开发服务器（VitePress 的本地搜索索引在页面增删时会出错，
重启可以绕开这个上游问题）。

## 目录结构

```
docs/
  site.json                     站点级设置：站名、作者、摘要、图标、站点网址、
                                页脚文案、评论区参数、书架分组
  index.md                      书架首页（生成物）
  novels/
    _模板/                       新作品从这里复制（下划线开头，不进站点）
    持续存在/                    一部作品，文件夹名随便取
      novel.json                标题、网址、简介、状态、许可
      01-导语.md … 18-后记.md    正文，文件名前缀决定目录顺序
      00-作品许可证（网站）.md    可选：许可声明，网址固定为 <作品>/license
      cover.png                 可选：封面（海报式竖图最好，需在 novel.json 里写 cover 才上卡片）
    邓煜语录/                    正文、图片、原始 PDF 都放在一起
  public/
    favicon.png                 站点图标 64×64（由 site.json 的 icon 生成）
    apple-touch-icon.png        iOS 加到主屏用 180×180（同上）
    fonts/noto-serif-sc-subset.woff2  阅读用宋体子集 408KB（已入库）
    novels/<slug>/cover.jpg     封面压缩产物（生成物）
    feed.xml                    订阅源（生成物）
    sitemap.xml                 站点地图（生成物）
    robots.txt                  爬虫规则（生成物）
  .vitepress/                    站点配置与主题
```

图片处理（站点图标、封面）用 **sharp**（项目的 devDependency），本地和
Cloudflare Pages 这类云构建环境都能出图，所以图标和封面不必靠「产物入库」兜底。
`docs/public/` 里那几个生成物（封面、feed、sitemap、robots）都在 `.gitignore` 里，
构建时会现生成。

几点说明：

- **网址**由 `novel.json` 里的 `slug` 决定（文件夹名可以是中文，网址用拼音/英文更清爽）；
  没写 `slug` 就直接用文件夹名。发布后不要再改 `slug`，改了等于换网址。
- **书架首页是生成的**（`docs/index.md`）：文件末尾有一行
  `<!-- generated by scripts/sync-content.mjs -->`，想自己写就把那一行删掉，脚本不再覆盖。
- **没有「作品首页」这一层**：书架上的书卡、顶栏里的书名都直接指向第一章。
  书名、作者、网址、简介、状态都写在各自的 `novel.json` 里，卡片上显示 tagline
  （没写 tagline 就显示 description）。
- 章节目录（侧边栏）、上一章/下一章、字数统计都是**直接读这些 md 文件**算出来的，
  没有中间产物，不会出现「目录和正文不一致」。

## 加一部新作品

1. 复制 `docs/novels/_模板/` 成 `docs/novels/<新书名>/`；
2. 改 `novel.json`（`slug` 建议用拼音或英文，**发布后不要改**）；
3. 把章节按 `01-第一章.md`、`02-第二章.md`…… 命名放进去，每篇正文第一个 `# 标题` 是章节名；
4. 跑 `pnpm docs:dev`，书架首页会自动多出一张卡片。

章节数量不限，顺序永远是「文件名前缀小的在前」。想在中间插一章，就在那个编号上插，
再把后面的文件依次顺延。

## 书架分组

首页不放横幅（hero），只有分组书架，站名显示在顶栏和浏览器标签上。
分组标题和先后顺序在 `docs/site.json` 的 `sections` 里改（`description` 可选，写了会显示在标题下方）：

```json
"sections": [
  { "id": "original",  "title": "我的作品" },
  { "id": "recommend", "title": "个人推荐书籍" }
]
```

页脚文案也在同一个文件里：

```json
"footer": {
  "message": "本站作品版权归各自作者所有，转载请注明出处",
  "copyright": "© sasaOrange"
}
```

`tagline` 会作为页面的 meta 描述（搜索引擎和分享预览用），同时显示在书架卡片上。

首页顶部的大字来自 `heroTitle`（下面那行小字是 `heroSubtitle`），两个都可以留空——
都留空的话首页就直接从分组书架开始：

```json
"heroTitle": "我的小书屋",
"heroSubtitle": "感谢你的到来"
```

顶栏和浏览器标签上显示的是 `title`，所以它写短一点（手机上不会被截断）。

`site.json` 里还有两个跟「分享 / 互动 / 收录」有关的键：

```json
{
  "url": "https://sasaorange-novel.pages.dev",
  "comment": {
    "provider": "giscus",
    "repo": "TruE-aL/sasaOrange-novel",
    "repoId": "",
    "category": "Announcements",
    "categoryId": ""
  }
}
```

- `url`：站点正式地址。`og:image`、canonical、订阅源与站点地图里的绝对链接都用它拼。
  不填也能构建，只是那些绝对链接会退化成占位域名。
- `comment`：章节页底部的评论区（giscus，基于 GitHub Discussions）。
  `repoId` / `categoryId` 还空着时，评论区**什么都不渲染**，站点不会出现一个空框；
  在 [giscus.app](https://giscus.app) 上按仓库生成这两个 id 填进来即可生效。

每部作品在自己 `novel.json` 里用 `category` 指定归到哪一组，不写就默认进第一组：

```json
{
  "title": "邓煜语录",
  "category": "recommend",
  "author": "邓煜"
}
```

`author` 和站点作者（`site.json` 里的 `author`）不一样时，卡片上会多显示一行「邓煜 著」，
一眼能看出这不是自己的作品。

## 书架卡片与封面

首页每个分组排成一格一格的「书卡」，整张卡可点，点了直接进第一章。

**封面是可选的，默认不显示**——卡片直接从书名开始排：书名、一行小字（章数 · 字数）、
一句话简介、「开始阅读」。想给某本书放封面，就在它的 `novel.json` 里显式写 `cover`：

```jsonc
// 不写 cover        → 卡片不显示封面（默认）
"cover": true        // → 用文件夹里的 cover.png
"cover": "x.png"     // → 用指定的那张图
```

- 封面图会被压成 900px 宽的 jpg，竖版海报效果最好（卡片按 3:4 裁切）。
  之所以改成"显式开启"，是因为早先会自动去找 `cover.png`，
  文件夹里恰好有张图就直接上了卡片，观感很突兀。
- `status`（已完结 / 连载中 / 语录集…）那枚小圆标印在封面右上角，**没封面时不显示**。
- 有阅读进度的书，书卡会加一圈主题色提示：有封面时描在封面外圈，
  没封面时改在书名左侧点一小段竖条（`.shelf-card.is-continuing`）。

## 目录上显示的名字

目录项分成两截排版，像书前的目录页：

```
序章      阿美寮
第1章     思念报复
第11章    无风
```

- 章节号默认取文件名（`03-第一章.md` → 第一章），显示时统一转成阿拉伯数字（`第十一章` → `第11章`），
  这样在窄目录栏里不会顶到章节名上
- 章节名默认取正文里第一个 `# 标题`（`# 思念报复` → 思念报复）
- 章节号和章节名完全重复时只显示名字（`# 序章` 就是「序章」）
- 标题里自己写了章节号（`# 第一章 思念报复`）会自动剥掉，仍按「第1章 ｜ 思念报复」显示
- 想手工指定，就在那篇开头加 frontmatter：

  ```yaml
  ---
  label: 第1章
  title: 思念报复
  ---
  ```

样式在 `theme.css` 的 `.toc-num` / `.toc-title`，想换成上下两行、或者只留章节名，改这几条规则即可。

## 把 PDF / 其他格式变成网页

以《邓煜语录》为例（原文件是 10 页 PDF）：

```bash
pdftotext -layout 原件.pdf 文本.txt      # 提取文字
pdfimages -j 原件.pdf 图片名              # 抽出内嵌图片
```

然后把文字整理成 `NN-作品名.md`（段落并成行、页码丢掉、脚注写成 markdown 的 `[^1]`），
图片放进同一个文件夹用相对路径引用（`![说明](图片.jpg)`），原 PDF 也留在文件夹里存档。
VitePress 会把这些图片打包进站点。

语录、随笔这类不是「第N章」结构的作品，`novel.json` 里的 `status` 可以写「语录集」，
书架卡片会显示成「语录集 · 1 篇 · 约 0.2 万字」。

## 阅读配色

站里有三套配色，顶栏右侧的小圆点可以切换（手机上展开右上角菜单，在菜单最下方），
选择记在浏览器的 localStorage 里，每台设备各记各的。

**默认值按页面分**：没手动选过的读者，打开**书架首页**看到的是**淡橙红**（当门面），
进入章节等其它页面则是**护眼的暖黄**；读者一旦点过色卡，就按他自己选的来，全站一致。
想让某台设备回到「跟随页面默认」，**再点一次当前选中的那个色卡**即可
（控制台 `localStorage.removeItem('novel-color-scheme')` 效果相同）。

- **暖黄（默认）**：米黄纸感底色 + 琥珀色强调，长时间阅读不刺眼
- **淡橙红**：暖白底 + 橙红强调（和 orange 这个名字呼应）
- **淡蓝**：与作品许可页同一套蓝

色值和明暗模式都在 `docs/.vitepress/theme/theme.css` 里：
`:root` / `.dark` 是暖黄，`html.theme-orange(-.dark)` 是淡橙红，`html.theme-blue(-.dark)` 是淡蓝。
（早先那套淡绿已换成淡橙红，`novel-color-scheme` 里存过 `green` 的读者会被自动映射过来。）
想再加一套：在 `theme.css` 里补一段 `html.theme-xxx` 变量，再去
`docs/.vitepress/theme/SchemeSwitch.ts` 的 `SCHEMES` 里加一项，
最后把新配色名字加进 `config.mts` 首屏脚本的白名单。

卡片、设置面板这些地方的投影也用变量（`--novel-shadow-sm/md/lg`），
每套配色定义自己的 `--novel-shadow-rgb`（暖黄偏棕、淡橙红偏橙、淡蓝偏蓝），
深色模式统一换成黑影——所以切配色时阴影不会「发脏」。改成一整套阴影也行，
直接覆盖那三个 `--novel-shadow-*` 变量即可。

## 阅读设置（字号 / 行距 / 字体 / 版心）

章节页顶栏右侧有个 **Aa** 按钮，点开可以自助调整：

- **字号** 14–32px
- **行距** 1.5–2.6
- **字体** 宋体（默认，下面那节的思源宋体子集）/ 黑体（系统默认）
- **版心** 480–1400px（**仅桌面端**）：正文那一栏的最大宽度，想让文字排得宽一点就拉大

只在正文页显示（其它页面改了也看不出效果），选择记在 localStorage 里，
首屏脚本会在渲染前先应用，所以刷新不会闪一下。默认值在
`docs/.vitepress/theme/ReaderSettings.ts` 的 `DEFAULTS` 里。

## 章节目录折叠与「重置阅读进度」

章节页左侧目录的上方有一条小工具条，两个按钮：**左＝清空阅读记录，右＝收起/展开目录**。
和目录同色（`--vp-c-brand-1`），带边框，按下有反馈。手机上（<960px）不渲染。

**手机上换个位置放**：抽屉式的目录里，这条工具条够不着（抽屉是独立的一层），
所以在目录列表末尾、**右下角**单独放了一枚「重置阅读进度」（`theme/MobileClearHistory.ts`，
挂在 `VPSidebar` 的 `sidebar-nav-after` 插槽）。它右端与章节**选中块的右缘对齐**，
外观和桌面端那枚一致，点一下同样会短暂变成对勾。
两个组件共用 `readingProgress.ts` 的 `clearAllReadData()`，行为完全一致；
各自判各自的断点（≥960px 归桌面工具条、<960px 归抽屉），不会重复渲染。

**目录默认是收起的**，只有点按钮才展开。状态**不做任何记忆**：

- 从书架点「开始阅读」进来 → 收起（每次都从头开始，不会突然冒出个目录）
- 目录里翻到下一章 / 上一章 → **保持当前状态**（读到一半目录不会被收走）
- 回到书架首页等非正文页 → 收起，下次进来仍是收起态

实现要点：

- 收起不是 `display: none`，而是把侧边栏 `width` 过渡到 0——这样才有「推着正文走」的动画，
  正文的左侧留白同步减少（`theme.css` 第 7 节的 `@media (min-width: 960px)` 块）
- 状态类 `novel-sidebar-collapsed` 挂在 **`<html>`** 上，而 `novel-chapter`
  由 VitePress 按 frontmatter 挂在 **`div.Layout`** 上——两者位置不同，
  选择器必须都顾及（写成 `html.novel-chapter` 永远匹配不到，动画会失效）
- 首屏在 `config.mts` 的防闪烁脚本里**提前加好** `novel-sidebar-collapsed`，
  避免先渲染出展开的侧边栏、再「唰」地收回去
- 组件在 `theme/SidebarToggle.ts`。判断「是否刚进这本书」用的是 `watch(visible)`
  而不是 `onNavigationEnd`——组件实例在「章 → 章」之间会被 Vue 复用，
  只有 `visible`（`pageClass === 'novel-chapter'`）才会在「进出这本书」时翻转
- 那份避让「本页目录」的 CSS（960–1279px 区间）：该区间 VitePress 会把右侧目录
  搬成顶栏里的一条「本页目录 ›」，工具条专门往左挪了 62px 让开它
- 手机端按钮的水平对齐：抽屉内容区左右各留 32px，选中块右缘实测落在内容区右界
  往里 8px 处，所以按钮用 `margin-right: 8px` 对齐（四种常见宽度实测偏差 0px）

## 继续阅读

读者在某一章读到一半、下次回到书架，卡片上的「开始阅读」会变成
**「继续阅读 · 第6章　裂痕」**，点了直接跳回那一章，卡片上还会加一点主题色提示
（有封面时是封面外圈的一环，没封面时是书名左侧的一小段竖条）。
侧边栏目录里读过的章节，标题后面也会点一个小圆点。

卡片指向的是**这本书最近打开过的那一章**，跳过去也是从那一章开头读，不恢复章内位置。
这是纯客户端能力，不影响任何未读过的读者：没有记录时书卡就是普通的「开始阅读」。

⚠️ 「继续阅读」和目录小圆点用的是**两份独立存储**，语义不同，别混用：

| 存储键 | 记什么 | 语义 | 用在哪 |
| --- | --- | --- | --- |
| `novel-read` | 读完过哪些章 | **严格**：读到 90% 才算 | 目录里的已读小圆点 |
| `novel-last` | 最近打开过哪一章 | **宽松**：进去就算 | 书架卡片的「继续阅读」 |

早先图省事，让「继续阅读」也从 `novel-read` 反推，结果读者在某章读到一半就离开时
那一章进不了已读集合，卡片只能指向上一个「读完过」的章——表现就是
*「明明刚在读第 4 章，回书架却还显示继续读第 1 章」*。拆成两份后各按各的语义走，互不干扰。

`novel-last` 结构是 `{ [作品路径前缀]: 章节路径 }`，每部作品只留一条最新值：

```json
{ "/novels/chixucunzai": "/novels/chixucunzai/04-第二章" }
```

实现上分两处：每部作品的章节清单随首页注入到 `<head>`
（`docs/.vitepress/config.mts` 的 `transformHead`，因为 markdown 里的 `<script>`
会被 VitePress 过滤掉），客户端逻辑在 `theme/shelf.ts`。
`readingProgress.ts` 在「已读状态变化」时会回调 `shelf.ts` 即时刷新目录小点
（方向单向：`shelf → readingProgress` 注册回调，避免两个模块互相 import 成环）。

## 阅读记录（已读章节）

只记**「读到过哪些章节」**，不记滚动位置——所以任何一次进入都从文章头开始读，
不会出现「从书架点开始阅读，正文却停在上次读到一半的地方」。

数据存在 localStorage 的 `novel-read` 里（`docs/.vitepress/theme/readingProgress.ts`），
路径统一成不含 `.html` / `?query` 的干净写法。
（另有 `novel-last` 记「最近打开过哪一章」，只服务书卡的「继续阅读」，
语义与判定都更宽松，详见上面「继续阅读」一节。）

**判定标准：读到本章 90% 才算已读。** 不用「距页尾 40px」那种固定像素差，
因为它跟章节长短无关——长章节末尾留白多、短章节 40px 占比很大；改用比例后长短章节一视同仁。
页面短到没有可滚动空间（一眼看完）时不算已读，否则一进来就自动亮点了。

⚠️ 「读到底」只在**读者自己滚动**时判定，全程不看切页那一刻的滚动值——
VitePress 的路由在切页瞬间会自己滚一下（实测停在顶部点「下一章」，
`scrollY` 会在半帧内冲到 `scrollHeight`），那个值不可信，用它会把刚翻开
没读的章节误标成已读。所以：

- 读者滚到 90% 的那一刻 → 立即标记（`onScroll` 里实时判）
- 离开这一章时 → **只负责「没读到底就收回小点」，不做补记**；
  且用切页前记下的位置判断，并用一道 `frozen` 闸门挡住紧随其后的假滚动事件
- 刷新 / 关标签页 → 走 `beforeunload` / `visibilitychange`，实时位置可信，正常记录
- 「已读」表示「这一章读到过尾」：重新打开一章、没读到底就走了，小点会收回去

> `novel-last` 不受上述「读到底」判定影响——它宽松，进入章节页（`onNavigationEnd`
> 里 `isReadingPage()` 为真）就更新，只切到书架/首页时不动，所以不会把目录页记进去。

想清空所有记录：**桌面端**在章节页目录上方的工具条、**手机端**在抽屉目录末尾，
各有一枚「重置阅读进度」按钮，会一次性把 `novel-read` 与 `novel-last` 都抹掉；
也可以在浏览器控制台里 `localStorage.removeItem('novel-read')`。
记录最多保留 120 章，超出丢掉最早的。

### 进度条与加载条

正文页顶部还有一条 3px 的进度条（`theme/ReadingProgress.ts`，写法借鉴 sakurairo 的
`.iro-scroll-percent`），宽度就是已读百分比；只在正文页显示，首页与许可页不显示。
想换颜色就改 `theme.css` 第 9 节里的 `background-image`，不想要就把 `theme/index.ts`
里 `'layout-top'` 那一行删掉。

切页时顶部还会出现一条更细（2px）的加载条，见 `theme/NavProgress.ts`——实现思路
借自 sakurairo 用的 `vitepress-plugin-nprogress`，但没引依赖、自己写了 30 行：
跳转开始后**延迟 120ms** 才出现（静态站通常几十毫秒就读完了，这样不会闪一下），
结束时补到 100% 再淡出。不想要就把 `theme/index.ts` 里的 `installNavProgress()` 删掉。

访问不存在的地址时的 404 文案也是中文的，写在 `docs/.vitepress/config.mts` 的
`themeConfig.notFound` 里（`title` / `quote` / `linkText`）。

## 切页动画

切章节时，正文会从下方 22px 处淡入（0.5s），章名再单独「落下来」（1s，前一半先藏着）。
效果借自 [KeqingMoe/sakurairo](https://github.com/KeqingMoe/sakurairo)（VitePress 版的
Sakurairo 主题，GPL-2.0）里 `Post.vue` 的 `iro-main` / `iro-fade-in-down` 两条关键帧，
这里只取了视觉参数（位移量与时长），重新写成本站自己的 `novel-page-in` / `novel-title-in`。

实现要点（`docs/.vitepress/theme/theme.css` 第 8 节）：

- 动画挂在**页面组件的根节点**上。VitePress 的 `.vp-doc` 外层容器是常驻的，
  但它里面的页面组件每次切页都会重建，所以这条纯 CSS 动画会自动重播——**不需要任何 JS 钩子**，
  也就不会出现「钩子没装上就看不到」的情况
- 章节页与许可页用 `.novel-chapter .vp-doc > div` / `.novel-license .vp-doc > div`；
  首页多套了一层 `VPHomeContent`，用 `.VPHomeContent.vp-doc > div > div`
- 尊重系统「减弱动效」：`prefers-reduced-motion: reduce` 下这些动画会关掉
  （第 8 节末尾那段 media query，书架卡片的位移也在里面一起关掉）
- 调快/调慢就改那两处 `0.5s` / `1s`，以及关键帧里的 `translateY(22px)`；
  不想要就删掉第 8 节整节

### 为什么要有 theme/navigation.ts

**VitePress 2.0.0-alpha 已经不再用 vue-router 了**，它自带一个极简路由，钩子是单个属性
（`router.onBeforePageLoad` / `router.onAfterRouteChange`…），没有 `beforeEach` / `currentRoute`。
（上游 `EnhanceAppContext` 的类型声明还是旧的 vue-router 的 `Router`，但运行时对不上。）

所以阅读进度、加载条、书架增强这三个模块**不能各自去给 `router.onXxx` 赋值**（会互相覆盖），
而是统一登记到 `theme/navigation.ts` 的监听表里，由它挂一次钩子，再用
`onNavigationStart` / `onNavigationEnd` 分发。加新的「切页时要做事」的功能，也走这里。

（顺带：如果以后升级 VitePress 拿掉了这些钩子，只有这一个文件需要跟着改。）

## 阅读字体

「宋体」用的是自托管的思源宋体（Noto Serif CJK SC）子集：
`docs/public/fonts/noto-serif-sc-subset.woff2`，只包含作品实际用到的两千多个字，**408KB**。

它是**默认字体**（`--vp-font-family-base` 首选就是它），所以几乎所有第一次来的读者都会加载它；
章节页的 `<head>` 里也加了 `<link rel="preload">`，让字体早一点到位、少闪一下。
读者在阅读设置里切到「黑体」时，就不再需要这个字体文件了。

```bash
pnpm fonts:build        # 重新生成子集（新章节出现生僻字时跑一次）
```

这个脚本从系统字体 `NotoSerifCJK-Regular.ttc` 里取字（可用环境变量
`NOTOSERIF_PATH` 指定别的路径），需要 Python 的 fontTools 与 brotli：
`pip install fonttools brotli`。没覆盖到的字浏览器会自动回退到系统衬线字体，
不会出现豆腐块。字体许可是 OFL 1.1，声明见 `docs/public/fonts/LICENSE.txt`。

## 订阅与收录

构建时会顺带生成三个文件到 `docs/public/`（都在 `.gitignore` 里，不必入库）：

- `feed.xml`：订阅源。把每一章当成一条「更新」，**按 md 文件的修改时间倒序**排，
  所以改过哪一章，订阅里就会浮到最前面——不用另外维护「更新日期」字段。
  页面 `<head>` 里有 RSS 自动发现的 link，读者用阅读器订阅站点即可。
- `sitemap.xml`：站点地图，收录首页、每章、许可页。
- `robots.txt`：允许抓取，并指向站点地图。

三者里的绝对链接都来自 `site.json` 的 `url`。

## 部署

站点部署在 **Cloudflare Pages**，项目名 `sasaorange-novel`，
正式地址是 `https://sasaorange-novel.pages.dev`。

配置写在项目根目录的 `wrangler.toml`：

```toml
name = "sasaorange-novel"                  # 决定默认域名 sasaorange-novel.pages.dev
pages_build_output_dir = "docs/.vitepress/dist"
```

### 自动部署（推荐，日常就用这个）

仓库里已经配好 `.github/workflows/deploy.yml`，三种触发方式：

| 触发 | 结果 |
| --- | --- |
| push 到 `main` | 部署**生产环境**（`sasaorange-novel.pages.dev`） |
| 打开 / 更新 PR | 部署**预览环境**，并在 PR 里自动回帖预览地址 |
| 手动触发 | 部署生产环境 |

生产流程：

```
push 到 main
  → 装 pnpm（读 package.json 的 packageManager 字段）
  → pnpm install --frozen-lockfile
  → pnpm docs:build
  → wrangler pages deploy → sasaorange-novel.pages.dev
```

PR 预览用**源分支名**做部署分支，Cloudflare 会据此生成
`<分支名转义>.<项目名>.pages.dev` 的预览地址（转义规则：转小写、非字母数字压成单横线、
去掉首尾横线，和 Cloudflare 的 branch alias 一致）。每次推送都会更新同一个预览地址，
工作流再把链接回帖到 PR 评论里，点开就能看。

想手动跑一次，去 **Actions → Deploy to Cloudflare Pages → Run workflow**。

它依赖仓库里的两个 Secrets（**Settings → Secrets and variables → Actions**），
首次配置时需要自己建：

| Secret | 从哪来 | 需要的权限 |
| --- | --- | --- |
| `CLOUDFLARE_API_TOKEN` | Cloudflare → My Profile → API Tokens → Create Custom Token | `Account` / `Cloudflare Pages` / **Edit** |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare → Workers & Pages → 右侧栏 Account ID | — |

> 别用 Global API Key，范围太大；自定义 Token 只开 Pages 的 Edit 就够。

**「推上去没反应」先查这里**：Secrets 名字拼错（大小写敏感）、Token 权限没给 Edit、
或者 Cloudflare 上项目名不叫 `sasaorange-novel`（名字对不上 wrangler 会去新建一个项目）。

### 手动部署（备选）

不想等 CI、或者要在没配 Actions 的环境发一次：

```bash
npx wrangler login        # 登录一次即可
pnpm docs:deploy          # = pnpm docs:build && npx wrangler pages deploy
```

首次如果提示项目不存在，先跑一次 `npx wrangler pages project create sasaorange-novel`。

### 另一种做法：Cloudflare 连 Git 仓库

在 Cloudflare 控制台新建 Pages 项目并连上这个仓库，构建命令 `pnpm docs:build`、
输出目录 `docs/.vitepress/dist`。

⚠️ **和上面的 GitHub Actions 二选一**——两个都开会对同一次推送部署两遍。
图片处理用的是 sharp（devDependency，装依赖时一并装好），云端没有 ImageMagick 也能出图。

### 几个注意点

- `name` 决定默认域名，**首次部署后不能改**，想换的话得在部署前改（否则只能重建项目）。
- 部署前记得把 `docs/site.json` 里的 `url` 改成真实域名，`og:image`、canonical、
  订阅源和站点地图里的绝对链接才正确。
- 构建产物 `docs/.vitepress/dist` 在 `.gitignore` 里，所以无论哪条路径都是**先构建再上传**。

## 出问题了怎么排查

**页面白屏 / 内容不更新 / 改了配置不生效**：多半是 Vite 的缓存和磁盘上的代码对不上了
（新增主题文件、改配置、同时开过多个开发服务器时最容易出现）。

```bash
# 1. Ctrl+C 停掉正在跑的开发服务器（必须停，运行中清缓存没用）
# 2. 清缓存
pnpm docs:clean
# 3. 重新启动，然后在浏览器里硬刷新（手机上：关掉标签页重新打开，或清除站点数据）
pnpm docs:dev
```

还不行就看浏览器控制台的红色报错——那是客户端真正抛出的错误，把第一行发我就能定位。

**只用 curl 检查时注意**：开发服务器对任意路径都返回那个只有
`<div id="app"></div>` 的空壳（内容由浏览器端渲染），所以 curl 看不到正文是正常的；
要确认产物有没有内容，用 `pnpm docs:build && pnpm docs:preview`。
